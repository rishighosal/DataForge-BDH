A fixed-size matrix can remember thousands of facts — until the facts start writing over each other.

A Transformer remembers every token it has seen by keeping an explicit, ever-growing key–value cache. BDH remembers differently: it folds each new fact into one constant-size synaptic matrix using an outer-product, Hebbian write — the same operation researchers call a fast weight.

Below is a working copy of that trick, small enough to watch. You will store real associations into both memories, query them back, and watch the fast‑weight memory's answers get noisier while its size never changes.

The one falsifiable sentence

A constant-size matrix updated by outer-product ("Hebbian") writes can store and retrieve many key→value associations with no memory growth — but retrieval quality degrades in proportion to how many associations share that fixed capacity, while a Transformer's explicit key–value cache never degrades because its memory grows with every token it stores.

This is not textbook trivia. Two 2026 papers — Gated DeltaNet‑2 and Variational Linear Attention — exist specifically to fight the degradation you're about to reproduce below, by adding correction and forgetting terms to the same outer‑product update. If the sentence above is wrong, cranking the sliders below should fail to show it. Try to break it.

Guided walkthrough

Same 16‑dimensional memory. Only the number of stored facts changes.

All three steps below use the identical outer‑product memory, dimension d = 16, identical random seed. The only variable is n, how many (key, value) pairs have been written. Watch the "estimate vs. truth" row and the matrix on the right.

STEP 1 OF 3

n = 4, d = 16 — plenty of headroom

Four facts sharing 16 dimensions of capacity. Random 16‑dimensional vectors are nearly orthogonal, so the outer‑product writes barely overlap. Both memories answer correctly.

STEP 2 OF 3

n = 16, d = 16 — capacity fully spent

As many facts as dimensions. The cache is still perfect — it never has to share space. The fast‑weight matrix's answer is visibly drifting from the true value: the other 15 associations are now leaking into every readout.

STEP 3 OF 3

n = 64, d = 16 — four facts per dimension

The cache is now 4× the size it was at Step 2, still perfect. The fast‑weight matrix hasn't grown a single byte — and its answers are approaching noise. This is the trade the whole family of "recurrent state" architectures makes.

Inside BDH

This is not an analogy. It's BDH's actual update rule.

The Dragon Hatchling paper defines working memory as a synapse strength σ(i,j) between neuron i and neuron j, updated during inference by:

σ(i,j) ← σ(i,j) + Y(i)·X(j)
— Dragon Hatchling, §1.2 (Pathway, arXiv:2509.26507). "Co‑presence... of Y(i) followed by X(j) increases σ(i,j) by Y(i)X(j)."

That is an outer‑product write — exactly the S ← S + k·vᵀ update running in the demo above, with Y playing the role of the key and X the value. The paper itself names this state "fast weights" and treats it as equivalent, in the relevant limit, to a linear‑attention edge‑reweighting. The one real difference: BDH's Y and X are sparse and non‑negative — about 5% of neurons active at a time (§6.4, "Empirical Finding 1") — rather than the dense random vectors used above. Sparsity changes how quickly capacity fills up; it does not change the mechanism.

BDH‑CQ (arXiv:2608.09888) reuses the same accumulation principle one level up: its contextual memory state accumulates additively as each demonstration is ingested, which the paper itself relates back to fast‑weight and linear‑attention views of contextual association — the same "write, don't replace" pattern, now applied to in‑context task demonstrations instead of individual tokens.

Evidence discipline — read this before citing the demo as "proof about BDH"

What the Dragon Hatchling paper documents: the exact outer‑product Hebbian update above, the "fast weights" framing, and ~5% activation sparsity.

What it does not publish: a retrieval‑accuracy‑vs‑capacity curve for its own synapse matrix. The collapsing curve you can produce in the sandbox is our toy demonstration of the general outer‑product / fast‑weight mechanism class — deliberately simplified to dense random vectors so the geometry is easy to see and to verify by hand.

Where that general phenomenon is independently documented: Titans (arXiv:2501.00663) motivates its entire memory module around it; Gated DeltaNet‑2 (arXiv:2605.22791) and Variational Linear Attention (arXiv:2605.11196) — both from 2026 — exist specifically to correct for it. The curve is real math, cross‑checked against the classical linear‑associative‑memory noise estimate similarity ≈ √(d / (d+n−1)), shown as the dashed line in every chart above. It is not, and is not presented as, a number BDH's authors measured.

Common misconceptions

Three ways to misread this demo

"Fixed‑size means infinite capacity."

No — it moves the limit. A growing cache is limited by memory bytes. A fast‑weight matrix is limited by interference. Neither escapes a limit; they trade which one you hit first.

"BDH's paper proved this exact curve."

No — see the evidence‑discipline box above. BDH's paper documents the mechanism; the interference curve is our toy demonstration of that mechanism class, cross‑checked against classical associative‑memory theory and the wider fast‑weight literature.

"KV‑cache eviction solves the memory problem for free."

Eviction and compression bound the cache's memory — but every evicted token becomes exactly as unrecoverable as an interfered fast‑weight association. It's a move toward the fast‑weight side of this same trade‑off, not an escape from it.
